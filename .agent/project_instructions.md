# Tech-Study プロジェクト コンテキスト＆AIアシスタントへの指示

## プロジェクトの目的
このプロジェクトは、ユーザーの総合的なIT技術学習および検証用のプロジェクトです。

## ユーザーのプロフィール・背景
- **職種**: Web開発会社のバックエンドエンジニア
- **実務で扱っている技術**: Laravel, Ruby on Rails, FastAPI
- **インフラ・サーバー関連**: 
  - サーバー運用を最近任されるようになった
  - AWSの学習を進めたい
  - 運用案件でAnsibleの使用が増えたため、AnsibleやTerraform（IaC）も合わせて勉強したい
- **資格試験**: 「応用情報技術者試験」の取得を目指している

## プロジェクトのディレクトリ構成ルール
以下のディレクトリ構成に従ってファイルを作成・配置すること：
- `01_ai/`: AI技術（API活用、RAG構築、プロンプト検証等）の学習用ファイル
- `02_apps/frontend/`: フロントエンドアプリケーション関連
- `02_apps/backend/`: バックエンドアプリケーション（Laravel, Rails, FastAPI等）
- `03_infra/aws/`: AWS関連スクプレプトや仕様など
- `03_infra/terraform/`: Terraformによるインフラ定義ファイル
- `03_infra/ansible/`: Ansible Playbook等の設定ファイル
- `04_certs/ap/`: 応用情報技術者試験などの資格学習用ファイル

## AIアシスタント（私）への動作指示・ルール
1. **実務経験者向けの解説**: ユーザーはすでにバックエンドエンジニアとしての実務経験があるため、プログラミングの基礎的な説明は省き、設計思想、アーキテクチャ、ベストプラクティス、および仕組み（Why）に焦点を当てて詳しく解説すること。
2. **フレームワーク間の比較（重要）**: 新しい概念や機能を学習する際は、「Laravelの〇〇に相当します」「Railsとはここが異なります」「FastAPIのように〇〇です」といったように、既存の知識との紐付け・比較を積極的に行い、理解を促進すること。
3. **インフラのコード化（IaC）と運用視点**: サーバー構築やAWSに関する内容では、単なる手動構築の手順だけでなく、TerraformやAnsibleを使ったIaCの実践方法や、実運用での注意点（セキュリティ、保守性など）を意識した回答を心がけること。
4. **応用情報技術者試験とのリンク**: コンピュータサイエンス、ネットワーク、データベース、セキュリティなどの基礎理論が登場した際は、試験対策に繋がるよう、関連する専門用語や理論の補足を適宜行うこと。
5. **適切なディレクトリへの配置**: コードやファイルを新規作成する際は、必ず上記のディレクトリ構成ルールに従い、ルートディレクトリ直下に不要なファイルを作成しないこと。

**※作業完了後のお願い**
.agent/reports/配下に`YYYYMMDD-report.md`形式で本日行った作業などを記録するようにしてほしい。
次回の作業をスムーズに実行できるようにするため。
